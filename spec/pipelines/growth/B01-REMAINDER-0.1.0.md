- 线上版本：未发布（`null`，无 tag）

## 范围

本文件只定义 0.1.0 内 B01 的剩余交付，不改变 0.2.0 预留，也不宣布 B01 完成。

1. **稳定救援批次与死亡优先**：同一稳定批次、完整事实和有效快照才可提交；死亡/失败优先于成功；旧批次、乱序事实和重复提交不得复活终态。
2. **效果派发资格**：效果请求按有序一次性身份消费；伪造、旧代次、错误阶段请求不得执行；清理效果与推进效果有明确先后。
3. **真实世界绑定**：Session 由宿主世界就绪事实进入 Rescue；迟到、解绑、旧世界回调不得写入当前轮次；Subsystem/Director 只做适配，不复制 Session 状态。
4. **真实 UE 回执与可见反馈**：核心命令只证明意图；必须在真实 UE 世界执行并取得对应可见反馈，不得用 NullRHI/核心用例替代。
5. **Win64 独立包**：完成 Cook/Stage/启动的最小包验证，保留构建与运行身份。

## 验收条件

- Linux 同源核心构建成功，现有 3 个用例和新增 3 个用例均实际执行、全部通过且无跳过；实际证据由 test 记录。
- 旧 `task/B01-completion` 的功能提交保留在 Git 历史中，经 tech 集成并通过 test 验证；治理文档不回退到旧 task/PR 模型。
- 真实 UE 世界就绪、旧世界回调隔离和可见反馈必须有实际运行证据；未执行时保持 NotRun。
- 独立包必须实际启动；不得以 Game/Editor 编译成功代替。
- 验收结论只写 `spec/evidence/evidence.md`；失败项原位更新，不新增平行报告。
- 不使用 hash/精确引文门禁；使用提交、稳定业务 ID 和执行链接。
