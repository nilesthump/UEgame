# narrative — 0.1.0 少量文本显示与字幕接入验收门槛

- 目标版本：`0.1.0`
- 文档性质：验收门槛定义，不是执行结果，也不是验收结论
- 适用工作项：`NAR-0.1.0-01` 文本真源；首批 `NAR-0001`–`NAR-0003`，不覆盖 B13 批量素材
- 当前结论：全部条目仍为 `draft`；技术导入、运行时显示、字幕、声音均为 `NotRun`；尚未接入
- 上游：`growth`；下游：`tech`；正式验收执行与结论归 `test`

本文定义“少量文本显示与字幕接入”的实际验收门槛，用于判断哪些文本条目可以从 `draft` 改为 `final`，以及何时允许进入 B13 声音素材准备。它不替代 [TEXT-SOURCE.md](../../contracts/narrative/TEXT-SOURCE.md) 的字段约定，也不写成运行时接入已完成。

## 1. 目的与边界

0.1.0 只验证**少量**文本能否在真实 UE 运行环境中被看见、被读成字幕。门槛的目的有三项：

1. 用最小样本验证 `TEXT.csv` 的稳定 `id` 能贯穿导入、显示和字幕，不被复制正文或另造编号；
2. 用实际观察结果决定单条文本是否达到 `final`，而不是按文档完成度或结构检查判定；
3. 只有达到 `final` 的条目才允许进入 B13 批量声音素材准备。

本门槛**不**覆盖：完整 B10 回访流程、B11 音频运行时、B13 素材制作、B15 全场集成与本人体验。治理结构检查通过、文本 CSV 格式检查通过，都不等于显示或字幕接入通过。

## 3. 技术导入：稳定 ID 不可替换

技术导入必须从本仓库 `TEXT.csv` 读取，并保留以下字段原值：`id`、`speaker`、`scene_or_result`、`status`。具体要求：

1. **`id` 是跨系统唯一身份。** 运行时显示记录、字幕记录和声音绑定都引用同一个 `NAR-xxxx`；不得重新编号、不得用行号或生成键替换、不得为同一条目另造第二份正文。
2. **`CueId` 只是制作触发器说明，不是条目身份。** 允许技术侧增加 `CueId` → 运行时触发的映射，但映射必须能反查到稳定的 `NAR-xxxx`。
3. **不得复制正文另存为第二真源。** 导入可以产生缓存、资产或数据表，但修订入口只有 `TEXT.csv`；缓存必须带 `id` 且可重新导入。
4. **导入版本用 Git 提交标识。** 技术导入时应记录所消费的 narrative 提交；不使用文件哈希或精确引文作为交接门禁。
5. **导入不等于显示通过。** 导入成功、数据表存在、编辑器预览可见，都不能单独记为运行时显示或字幕证据。
6. **状态仍由 narrative 维护。** 技术为验证可以导入 `draft` 样本，但不得自行把 `status` 改为 `final`，也不得把验证导入写成已定稿或已批量制作。

## 4. 三项独立证据：显示、字幕、声音

运行时显示、字幕、声音是**三个独立证据**，分别证明不同环节。任何一项都不能替代另一项，也不能用两项推断第三项。

| 证据 | 证明对象 | 可接受的观察 | 明确不能替代 |
| --- | --- | --- | --- |
| 运行时显示 | 文本在目标 UE 运行场景的显示链中实际可见 | 实际运行场景中通过正常叙事路径或受控触发，目标显示层实际出现该 `id` 的正文；画面可读、完整、无占位符，说话者标识与 CSV 一致 | 日志/控制台输出、编辑器资产预览、数据表查看、字幕视图 |
| 字幕 | 独立字幕视图在运行时实际出现并与同一 `id` 对应 | 实际运行中字幕层出现该 `id` 的说话者与正文，出现和结束跟随该轮台词；不串行、不叠字、不吞字 | 显示层文本、日志、纯文本导出、外部文档、无字幕时的占位说明 |
| 声音 | 同一 `id` 的语音实际可听 | 运行时按绑定实际播放对应语音，说话者与文本匹配；属于 B11/B13/B15 的独立证据 | 字幕出现、显示文本、音频文件存在、TextFallback 降级 |

补充约束：

- **显示证据**要求真实 UE 运行环境中的实际画面，不接受仅日志、仅控制台或编辑器内预览。
- **字幕证据**要求独立的运行时字幕视图。字幕组件缺失时退回显示层或日志，只能记为字幕 `NotRun`/`Failed`，不能记为字幕通过。
- **声音证据**在本门槛中保持 `NotRun`：0.1.0 不制作声音或演出资产。显示或字幕通过不得被写成声音通过；反过来，声音未制作也不阻止文本条目按本门槛达到 `final`，但声音状态必须继续如实记为 `NotRun`，由 B11/B13/B15 另行取证。
- `TextFallback` 或其他降级路径只记降级状态，不能结清正常显示、正常字幕或正常有声验收。
- 每个 `id` 的显示与字幕必须各有独立观察记录；同一张截图或同一次描述不能同时充当两项证据。

## 5. 单条通过判定

一条文本只有在以下五项全部满足时，才算通过本门槛：

| 编号 | 条件 | 判定要点 |
| --- | --- | --- |
| G-1 | 导入可追溯 | 运行时导入记录能按 `id` 反查到 `TEXT.csv` 同 ID 行；`speaker`、`scene_or_result`、`status` 保留原值 |
| G-2 | 运行时显示实际通过 | 在目标 UE 运行场景中实际看到该条正文与说话者；正文完整可读，无乱码、截断、占位符或串条 |
| G-3 | 字幕实际通过 | 独立字幕视图实际出现同一 `id` 的说话者与正文，时序跟随该轮，无叠字、吞字或错条 |
| G-4 | 两项证据独立 | 显示与字幕分别记录观察，均指向同一 `id`、同一导入版本和同一运行；不能互相引用替代 |
| G-5 | 证据可复核 | 记录实际执行身份：narrative 提交、技术构建/运行标识、场景、触发方式、观察者、日期、逐项结果；不使用哈希或精确引文门禁 |

任一条件缺失即不通过：未执行、`NotRun`、跳过、零样本、仅日志、仅编辑器预览、仅导入成功、仅结构检查通过，均不能记为通过。正文是否一致由观察者按同 ID 行目视核对并记录；不以 SHA-256、文件摘要或逐字精确引文匹配作为自动门禁。

## 6. 状态流转、final 与 B13 解锁

TEXT.csv 的状态只有 `draft`、`final`、`retired`，本门槛不新增状态值。

```text
draft（当前）
  → 技术导入并完成真实运行
  → 逐 id 取得显示与字幕两项独立通过
  → test 记录实际证据
  → narrative 单独提交把该 id 改为 final
  → 该 id 才可进入 B13 声音素材批量制作
```

规则：

1. **先通过，后 final。** 只有同一 `id` 的显示和字幕都实际通过，并由 `test` 形成当前证据结论后，`narrative` 才能把该条改为 `final`。任一失败或未执行时保持 `draft`。
2. **final 是逐条的。** 不应把整个文件一次性改为 `final`，也不应让未验证条目搭车。改状态时在提交和 MR 中列出受影响 `id`。
3. **只有 final 能进入 B13。** B13 的批量声音素材只依据 `final` 条目准备；`draft` 和 `retired` 不得进入 B13 批次。`NAR-0004`–`NAR-0007` 在各自通过前同样不得进入。
4. **整体门槛通过需要三条样本全部通过。** 单条 `final` 只解锁该条；只有 `NAR-0001`–`NAR-0003` 都完成显示与字幕实际通过并转为 `final`，才可以把 0.1.0 的“少量文本显示与字幕接入”整体记为通过。
5. **修订会使证据失效。** `text`、`speaker`、`scene_or_result` 或 `production_notes` 发生实质变化后，该 `id` 原有显示/字幕证据不再对应当前文本：已 `final` 的条目应回退为 `draft`，重新做显示与字幕验证后才能再次转 `final`；修订提交必须列出受影响 `id`。
6. **显示链变化会使证据失效。** 字体、显示层、字幕视图、时序或触发映射变化若影响样本观察，受影响条目的证据应重取；不得沿用变化前的结论。
7. **声音不参与 final 判定，但必须独立记录。** 本门槛不以声音通过为条件；声音 `NotRun` 不阻止文本 `final`，但也不得把声音写成已完成。声音通过与否由 B11/B13/B15 的独立证据决定。
