## 2. 未来资产入场检查项

单个 CueId/SegmentId 或批次只有在下列检查均有实际结果后才能进入导入和验收；任一项缺失、未执行或失败，门禁保持未通过。

### 2.1 来源与授权

- 每个声音必须能说明来源（开放资源、合成或自有素材）、获取方式和加工链。
- 记录作者/发布者、来源地址、许可证名称及允许用途（游戏内使用、修改、再分发、商用限制等）。
- 许可证或授权不允许本项目用途的素材不得入场；来源不明、仅限个人试听或无权修改的素材不得使用。
- 音效优先匹配开放资源，并记录已查看的候选及匹配/不匹配理由。检索失败、工具不可用或未完成检索不能记为“无匹配”，也不能据此直接合成。
- 合成对白或音效时，记录合成工具、音色/参数来源、生成版本和使用条件；不得在运行时联网补素材。
- 不自行购买素材，也不用未授权预录来源替代开放资源或合成结果。

### 2.2 对白合成

- 只对 `status=final`、文本版本明确且绑定稳定 CueId/SegmentId 的条目制作；`draft` 或版本不明的条目不合成。
- 逐条核对准确文本、说话者、发音和语气；同一说话者保持音色和称呼一致。
- 文本修订后由 narrative 给出受影响 ID 和 revision，art 按受影响条目重做，并同步声音、绑定和字幕状态。
- 对白输出到 `Assets/Audio/Voices/`，记录只引用 `NAR-xxxx`/CueId，不复制剧情正文另存。
- 无声占位、`TextFallback` 或临时静音文件不能当作对白完成。

### 2.3 开放音效优先

- 音效需求先检索可核验的开放资源；只有在没有合适匹配时才合成。
- 记录候选资源、试听结论和不匹配原因；不得用“没找到”代替检索记录。
- 循环音效必须标记循环属性，并确认循环点、循环长度和接缝；一次性音效标明触发场景和是否允许重叠。
- 音效输出到 `Assets/Audio/SFX/`；需要运行时的声音绑定和资源引用由 tech 按导入清单接入。

### 2.4 听辨、噪声、削波与循环

- 每个成品必须实际播放听辨，不能只检查文件存在、时长或波形截图。
- 检查并记录：异常噪声/底噪、削波/爆音、首尾静音或延迟、音量相对一致性、对白可懂度。
- 循环音效检查循环接缝是否有爆音、断点、节奏跳变或多余尾巴；不通过必须修复后重新听辨。
- 记录听辨人、时间、播放环境（耳机/扬声器）、文件版本和结论；未实际听辨不得记为完成。
- 独立包试听由 test/B15 在实际包中取证；源文件试听、占位音或字幕降级都不能替代正常有声验收。

### 2.5 导入清单

- 每个资产在清单中列出：CueId/SegmentId、源文件路径、目标 `Content/UEgame/Audio/...` 路径、资源名、文本 revision、时长、格式/采样率/声道、循环标记、许可证/署名引用。
- 清单必须与实际源文件一一对应：无缺文件、无孤立文件，tech 可按清单复现导入。
- 清单包含 SoundWave 导入设置、资源引用和 Cook 清单核对项；由 tech 执行导入和引用接入，art 不直接写 `Content/**`。
- tech 按清单导入，不自行改剧情文本、补素材或替换来源；发现不一致时退回 art 修正。
- 资产身份使用稳定 ID、CueId、Git 提交和实际执行链接，不使用 SHA-256、二进制摘要或精确引文作为准入/合并门禁。

### 2.6 署名

- 需要署名的素材记录署名文本、署名位置、传递对象和许可证要求；不需要署名的记录许可依据。
- 署名信息同时进入来源/加工记录和导入清单，不能只留在聊天、临时文件或个人备注中。
- 许可证文本或稳定来源链接随记录保存；许可条款变化时重新核对受影响资产。
- 署名遗漏、署名与许可证不一致或使用条件不清晰时，资产不得交付。

### 2.7 来源/加工记录与版本

- 在 `Assets/Provenance/Audio/` 维护素材请求、来源、加工/合成、听辨和导入记录，覆盖每个 CueId/SegmentId。
- 记录候选取舍、检索或合成理由、工具版本、输入、加工链、听辨结论和当前版本。
- 检索/生成临时文件放在忽略的 `Assets/Incoming/`、`Assets/Generated/`；`Assets/Audio/**` 只放明确需要版本化的制作源文件。
- 记录版本与文本 revision、导入清单、Git 提交对应；历史变更由 Git 保存，不新增平行结论文件。

## 3. 解锁顺序

1. narrative 将相关条目改为 `final` 并给出 revision。
2. tech/test 完成少量文本的 UE 显示/字幕接入验证，并更新 [evidence.md](../../evidence/evidence.md)。
3. tech 确认稳定 CueId/SegmentId 批次、目标路径、导入规格和验收方式。
4. art 按第 2 节逐项完成来源检索/合成、听辨、记录和导入清单。
5. tech 按清单导入，test/B15 在实际包中试听并取证。

在以上步骤有实际结果前，art 不开始新的制作批次，状态保持 Blocked。解锁不以口头承诺、计划文档、占位文件、未推送分支或未合并提交为依据。
