# 001 性能契约：输入至渲染反馈 < 50 ms

状态：**用户已明确端到端目标；尚未运行测量**。来源：[仓库初始化及性能指示](../requirements/001-causal-prototype/sources/2026-11-06-repository-bootstrap-and-latency.md)。用户先明确“输入到画面反馈小于50ms”，随后补充“输入→核心处理→渲染在50ms内”。

## 必须满足的目标

同一次有效输入从客户端接收，到首个包含该输入对应可见反馈的呈现帧，端到端延迟应小于50ms：

`Latency(InputId) = FeedbackFramePresentedAt - InputReceivedAt < 50 ms`

该链包含输入排队、核心规则处理、必要的UE世界处理、渲染排队/执行及呈现等待。50ms不是单帧预算、20FPS目标或纯核心每步预算，也不能由平均帧率推算。各线程可能重叠，不能简单相加CPU/GPU阶段耗时替代同一输入的总时间线。

起点按客户端收到事件定义；设备按下到客户端收到的硬件/OS额外延迟单独标明。终点须关联真正包含反馈的帧，不把空帧、回调返回、CPU提交渲染命令、GPU提交或“准备Present”误当实际画面反馈。若工具只能取得内部代理时间戳，报告证据范围与误差，端到端未得到证实前保持未验证；需要时用外部高帧率影像或相应呈现证据交叉核对。

## 关联与场景

性能记录使用开发诊断InputId和既有Run/ControlEpoch/ActionKey关联，记录输入接收、核心处理边界、实际状态变化、反馈帧和呈现证据。测量不得修改事实顺序、等待窗口或玩法判定；诊断本身的开销要报告。

覆盖移动/转向与相机、视角/地图操作、挥砍、发射物按住瞄准及松开发射，并在五敌/多弹体、切树/倒木、火雨/动态导航、语音字幕和快照保存压力下测量。刻意设计的前摇、跳时遮罩及拒绝条件按既有玩法保留；从输入到其最早应出现的合法可见反馈测量，不能为了50ms跳过规则，也不能把长时间无反馈改标为“等待动画”而免测。故障暂停/恢复等非普通操作阶段单列实际耗时及阶段身份，不无标记从慢样本中删除。

每次记录实际CPU/GPU/内存、OS/驱动、UE/编译器、构建及内容身份、分辨率/画质、窗口/同步/帧限制、输入设备/模拟方式、测试场景、冷热启动和采样方式。具体测量机、显示设置及场景采样计划由B14/B15在执行前固定并留证，目前未承诺硬件范围或样本规模。

## 通过判断与任务责任

保留原始逐输入样本、未匹配输入、漏帧、最大值、分布和所有≥50ms样本；P50/P95/P99可帮助诊断，但不能用均值或分位数掩盖明确的超标。测量误差可能跨越50ms时标为无法证明通过。当前只能对明确测试条件和覆盖范围给结论，不宣称所有机器上绝对保证。

- B02固定不扰动玩法的关联契约；B05/B06及对应领域暴露必要诊断边界。
- B14准备可追溯的测量记录与验证入口；不得把RepositoryBaseline结果当性能结果。
- B15负责端到端集成、实际测量、超标定位及最终结论；各模块owner处理所属瓶颈。
