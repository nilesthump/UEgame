## 已确认方案与技术栈

已确认采用 **C++ 显式状态机、相互独立的三个起点、分开的世界运行时间与实际耗时，以及结算完成后统一判定结果**。

| 技术 | 用途 | 原因 |
| --- | --- | --- |
| C++ UENUM / USTRUCT + 显式转移函数 | 在已确认的 UExperimentSubsystem 中推进阶段，状态放在 FExperimentRunState | 阶段少，转移条件直接可查；便于逐条核对成功、失败与等待发现条件 |
| 类型化函数 / UE Delegate | 传递发现、招式使用、朝哥布林攻击、死亡、结算完成、回访进度等事实 | 明确事件语义，避免用伤害事件代替使用统计 |
| 本轮世界时间轴 + FTimerManager | 正常运行时以 UWorld::GetTimeSeconds() 的本轮差值安排事件唤醒 | 世界事件服从暂停与运行速度；有固定时间点的计划可在跳时中补齐结算 |
| FPlatformTime::Seconds() | 用单调现实时间差计算三阶段实际耗时 | 不受剧情跨越 30 年或调整系统日历时间影响 |
| UDataAsset | 保存阶段表现参数、预设因果结果、环境计划配置 | 数值可调；需求已固定的雨时点与分支规则保持不变 |
| Blueprint / UMG | 接收允许展示的阶段信息、播放过渡、报告对话内容已送达 | 表现与结果判定分工明确，避免提前泄露分支 |

UE 定时器支持延迟调度、取消与暂停，见 [Gameplay Timers](https://dev.epicgames.com/documentation/unreal-engine/gameplay-timers-in-unreal-engine)。本机 UE 5.6 的 World.h 已核验 GetTimeSeconds 在暂停时停止且受时间倍率影响；WindowsPlatformTime.h 的 Seconds 使用 QueryPerformanceCounter。这里只核对能力，不锁定 A03 的引擎小版本。

## 阶段与状态归属

| 阶段 | 进入和离开条件 |
| --- | --- |
| Preparing：准备 | 清理上轮、恢复实体并等待必需模块就绪；完成后统一启动本轮世界 |
| Rescue：救援现场 | 世界启动即进入；内部区分未发现、已发现活体遇险、等待发现死亡后果。首次攻击不是进入该阶段的前提 |
| TimeSkip：跳时 | 仅救援成功进入；锁定救助方式与教师方向，结算旧时代环境并布置 30 年后的回访 |
| Revisit：回访 | 必要环境结算、回访布置与过渡表现均完成，玩家在镇上恢复行动时进入 |
| Ended：结束 | 规定失败时点或回访完成条件满足时进入；形成结果快照，等待人工重启 |

成功或失败是结束结果，不再各维护一套重复阶段。准备、结果展示/等待手动重启不计入三阶段耗时。5/2/3 分钟仍为调试目标，不新增超时失败；过渡表现以约 2 分钟调试，不能因时间到达就略过环境结算或回访准备。

回访完成用两个独立进度事实：已接收到体现学习风气的群众闲聊、已听到教师本人提起当年救援。两者顺序不限、已完成事实保持；只是触发对话或走近 NPC 不算听到关键内容。不要求听完整段，更不锁定玩家。内容送达检测细节留 A10。此完成条件不替代用户本人对“理解因果、感到世界改变”的体验验收。

## 三个起点与时间口径

| 起点 | 触发 | 影响 |
| --- | --- | --- |
| WorldStarted | 世界与参与者就绪后统一启动 | 遇险开始发展；旧时代时间轴第 180 秒开雨、第 300 秒停雨 |
| ThreatDiscovered | 玩家接近并发现仍受魔物威胁的小孩 | 从此收集使用过的剑术/魔法；发现前使用不补计 |
| FirstAttackDirectedAtGoblin | 本轮第一次朝哥布林发起已执行的挥砍或施法 | 开始日志救援计时，即使未命中；每次这类攻击都通知 AI 处理转向 |

三个起点独立存储，未发生时用“未设置”，不用 0 秒冒充。发现前已经朝哥布林攻击时仍应开启救援计时并触发仇恨，不自动补记“已发现”；投射物按发出时是否处于统计窗计入方式，不能因发现后命中而补计。

- **世界运行秒**：普通游玩以本轮 UWorld 时间差推进，默认 1:1；引擎暂停时停止，调试倍率可影响。雨计划用绝对本轮时间点保存，Timer 仅用于唤醒，不能成为计划是否完成的唯一依据。
- **实际耗时秒**：以单调现实时间差记录；阶段内的暂停和等待也计入，准备和结束后的等待不计入。这是本项已确认的日志口径，不新增暂停菜单或中途退出功能。
- **剧情年份**：成功跳时后增加 30 年，不把全局时间倍率设为 30 年，也不修改玩家年龄或剩余寿命。

救援耗时 = 首次朝哥布林攻击至离开 Rescue；从未攻击则为“未开始”。跳时耗时 = 进入 TimeSkip 至玩家在镇上恢复行动；回访耗时 = 恢复行动至回访双条件满足。没有进入的阶段标为“未发生”。

例：世界第 120 秒才首次攻击，在正常速度下第 180 秒仍开始下雨，此时救援日志只累计 60 秒；降雨不能推迟到首次攻击后的第 180 秒。

## 事实、结算与成败数据流

1. 世界 Director 确认本轮就绪，协调器创建新 RunId 并统一启动世界；所有延迟通知带当前 RunId，旧轮通知不进入新轮。
2. 感知与动作模块分别发出发现、招式使用、朝哥布林攻击事实。每次已执行招式使用 ActionId；同一动作的使用事实先于它的命中结果，未命中也不撤销已发生的使用统计。
3. 玩法模块处理碰撞、防反、生命值与死亡。对一次爆炸等多目标结算，必须处理完全部受影响目标，再通知当前结算批次已完成。
4. 本轮事实在游戏线程按发生顺序收集；同一玩法更新提交点先完成本批次所有已开始的伤害结算，再由协调器读取稳定的只读遭遇快照，判定一次。只读快照从领域状态生成，不新增第二份可写生命值。一次挥砍在不同帧命中的目标可属于不同批次，不为了等待未来命中而让流程无限等待；精确 Tick 安排在 A06 细化。
5. 发生终止结果后关闭救援输入与救助统计，按 A01 停止协议取消旧救援任务和在途攻击；保留需要结算的森林状态及雨计划。已提交的结果不受迟到通知再次改写。
6. 成功进入跳时与回访；失败进入结束。完整结果快照只在本次尝试结束时交给日志模块，成功路线不能在刚救出小孩时就填满回访耗时。

### 判定顺序（同一已完成批次）

| 条件 | 处理 |
| --- | --- |
| 玩家已死亡 | 本轮失败；若同时小孩死亡，原因事实一并保留，不丢弃同时发生的原因 |
| 玩家存活，小孩死亡，玩家此前已发现遇险 | 本轮失败；包括发现后离开、等小孩遇难的情况 |
| 玩家存活，小孩死亡，但尚未发现遇险/死亡后果 | 保留死亡现场，等待玩家发现后果；不进入教师后续 |
| 已在等待死亡后果，玩家发现该后果 | 本轮失败；此事实不打开活体遇险的救助方式统计窗 |
| 玩家和小孩均存活，五只哥布林已全部死亡 | 救援成功，锁定方式，进入跳时；不额外要求护送 |
| 其他情况 | 继续世界运行；转身离开不直接结束，五只哥布林可按规则回攻小孩 |

死亡条件先于清怪成功，因此同次火球造成“最后哥布林与小孩一起死亡”时不会先成功再失败。这里的优先级是对已确认失败规则的实现，不改变命中伤害规则。

### 方式与结果分开记录

统计窗内设置 SwordUsed / MagicUsed 两个标志，岩炮弹设置 MagicUsed。剑术、魔法各自使用过就保持为真；统计与命中次数、伤害大小、是否击杀分开。

玩家死亡导致本轮失败时，小孩可能仍存活；日志如实保留该状态，记录玩家死亡与未完成救援，不为归入“未获救”结果而补写小孩死亡，也不另行演算到其死亡。

| 本轮结果 | 方式统计 | 后续 |
| --- | --- | --- |
| 救援成功 | 仅剑术 | 剑术教师 |
| 救援成功 | 仅魔法 | 魔法教师 |
| 救援成功 | 两类都有 | 魔剑士教师 |
| 救援失败 | 保留实际方式，可能一类、两类或均无 | 不进入该教师后续；记录失败原因，不把方式改成“没使用” |

**已接受的场景约束，待 A04/A06 验证**：正常可成功的救援路径应在方式统计窗内产生至少一种招式使用；通过发现范围、现场视野及可介入位置布局覆盖该条件。发现前仍允许攻击、转移仇恨和开启救援计时，不把攻击本身当成发现、不追溯补算。若测试出现“成功但方式为空”，这是归类前提未满足的设计缺口，产生开发诊断并留待修正/必要取舍，不能伪造剑术、魔法或第四种教师分支。本项不增加该异常的玩家剧情路线。

## 跳时边界

成功只结束现场救援，不能丢弃未完成的环境因果。TimeSkip 必须向环境模块提交当前环境状态、旧时代已推进时间及尚未消费的计划，得到环境结算完成通知，再布置回访。剧情日期增加 30 年独立于上述时间轴。

例如世界第 20 秒已救援成功，即使过渡约 120 秒后结束，也必须在旧时代环境结算中覆盖原定第 180 秒的雨、第 300 秒的雨停及相关火雨/潮湿后果，避免雨被留到 30 年后的镇上才播放。已结算计划标记已消费，迟到的旧 Timer 不得再次改变回访。具体推进算法与表现交由 A09/A10 确认；本项只确定输入、就绪条件和阶段边界。

## 原因、核对例与下一步

- 显式阶段和独立起点避免把发现、攻击、世界启动误当成同一个时刻。
- 领域模块先完成结算、协调器后判定，避免多目标攻击和回调顺序改变故事结果。
- 实际耗时与世界/剧情时间分开，日志可比较，跳时仍能保留环境后果。
- 将方法统计、救援结果、教师分支和失败原因分开，失败记录仍保留玩家确实做过的事。

设计核对例：迟到发现尸体前不结束；从未攻击时救援耗时未开始；未命中攻击仍计时/计方式；发现前发出的火球发现后命中不补方式；同次攻击杀死小孩与最后哥布林判失败；早救援仍结算雨；回访两类内容任意顺序都可完成；旧 RunId 通知不改变新轮。这些是待实现后的验证用例，不是已运行通过的测试。
